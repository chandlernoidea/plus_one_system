## 2. 周视图的形态

390px 下 7 列每列只剩 ~50px，画等比时间轴看不了任何东西。所以这一页分成两段：

```
[抬头] 本周 5 单 · 11.02 – 11.08 · 占用 7.7 小时 · 空档 11 段
[7 列] 周一…周日，每列：星期 / 日期 / 单数 / 前 3 单的时间条（按状态着色）+N
[选中日] 11 月 7 日 周六 · 4 单 · 空档 3 段              [作业单 ↗]
         08:30–10:00 空档 可塞 90 分钟            [插一单]
         10:00–11:50 #C001 阿岚 已定档            [顺延]
         12:00–13:20 #C002 …                      [顺延]
[待通知] N 条：谁 / 什么变更 / 原时间 → 新时间 / [复制话术] [已发微信]
```

- **7 列只负责「今天哪几天忙」**：8px 的时间条，一眼能扫出这周哪里空、哪里挤。
- **下面只展开选中那一天**：空档、预约、操作都在这里，不用横向滚动，也不用点进二级页。
- 点右上「作业单 ↗」进 `/solo/today?date=YYYY-MM-DD`；作业单页支持用 `?date=` 指定日期，非当天时抬头显示日期而不是「今天」。

## 3. 三个交互

### 插队

从空档行点「插一单」→ 建单抽屉以 `mode="jump"` 打开（标题变「插一单」，提示「只能插进已释放的空档」）→ 走后端 `POST /api/solo/jumps`。

后端会先算当天空档，再校验「时长 + 缓冲 ≤ 空档剩余」，塞不下直接 409；插队的单来源记为 `JUMP`，作业单卡片上有「插队」标记。插队**不提供强排**——能插队的前提就是有空档。

### 顺延

预约行点「顺延」→ 抽屉里选分钟数（15/30/45/60 或自定义）→ 实时预览「影响 N 单」的原时间 → 新时间 → 确认。

- 预览走 `POST /shifts/preview`（只算不写），执行走 `POST /shifts`。
- 执行后逐单平移，并给每一单写一条 `solo_booking_change(notified=0)`，这就是「待通知清单」。
- 清单可从服务端读回（`GET /changes/pending`），不会因为刷新页面就丢；老板发完微信点「已发微信」把该条置为已通知。

![顺延抽屉](docs/screenshots/solo-shift.png)

### 强排

建单撞档时后端返回 409 + 冲突单摘要，抽屉里把冲突单摊开，并给一个「仍然强排」按钮（带 `force=true` 重发）。

强排后：作业单顶部出现「⚠ N 单时段冲突，已标红」，冲突的卡片描边转朱砂、加「时段冲突」标签。数据一条不丢，只是把冲突摆到明面上。

![冲突标红](docs/screenshots/solo-conflict.png)

## 4. 后端增量（本轮只加这三处）

| 改动 | 说明 |
|---|---|
| `BookingCreateRequest.force` | 为 true 时跳过冲突校验；默认 false，仍然 409 |
| `GET /api/solo/changes/pending` | 待通知清单（`notified=0` 的变更，带客户短号与昵称） |
| `POST /api/solo/changes/{id}/notified` | 标记一条已通知 |

## 5. 设计取舍

1. **顺延以「从哪一单开始」为入口，不做多选**。后端的语义本来就是「该时刻起整体平移」，前端多选反而会造出后端做不到的组合；点一单 → 预览里看清影响哪几单，足够。顺延后如果撞上别的单，后端会整批拒绝（409），不会改一半。
2. **待通知清单落库而不是只放内存**。brief 要求「生成待通知清单」，如果只是把顺延返回的数组画出来，刷新就没了，第二天也提醒不到人。落库 + 可读回 + 可标记，才是一条闭环。
3. **作业单的冲突数在前端算**。占用状态单两两比时间，一天十几单顶天，O(n²) 足够；这样不用为「冲突」再加一张表或一个字段。

## 6. 验收（390×844，Chromium headless + CDP）

```
PASS  周视图 7 列
PASS  点中明天的列 / 选中日详情列出 3 单 / 空档带「可塞 N 分钟」
PASS  顺延抽屉打开 / 预览列出影响 3 单 / 预览给出原时间 → 新时间
PASS  顺延后生成 3 条待通知 / 待通知时间正确（12:00→12:30、14:00→14:30、16:00→16:30）
PASS  标记已发微信后清单 -1
PASS  取消后卡片移出时间轴 / 取消后空档立即出现
PASS  插队抽屉以「插一单」打开 / 插队建单成功 / 插队单出现在时间轴上
PASS  撞档被拦并给出冲突摘要 / 冲突时提供强排按钮 / 强排后多出一单
PASS  作业单顶部提示冲突数 / 冲突单标红
PASS  非当天抬头不写「今天」 / 390px 无横向滚动
合计 26 项，失败 0 项
```

对应 brief 的两条验收：

- **取消一单后空档立即出现且能插入**：取消后天数段的空档从 0 段变 1 段，点「插一单」补到 10:00 成功，该日回到 1 单。
- **顺延 3 单后时间与通知清单正确**：3 单从 12:00/14:00/16:00 平移到 12:30/14:30/16:30，待通知清单 3 条，时间是「原 → 新」。

## 7. 复跑方法

```bash
cd backend
mvn -B -Dmaven.repo.local=target/m2repo -Daether.syncContext.named.factory=noop spring-boot:run &
bash target/seed-p4.sh          # 明天 3 单 + 后天 1 单（自带清理，可重复执行）
cd ../frontend && npm run dev -- --port 5173 --host 127.0.0.1 &
chromium --headless=new --no-sandbox --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-p4 --window-size=390,844 about:blank &
cd ../../backend && node target/verify-p4.mjs
```

`target/` 下的 `seed-p4.sh`、`verify-p4.mjs` 是本地验收工具，不入库。

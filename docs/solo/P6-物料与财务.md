## 2. 物料

### 今天要买的料

不是拍脑袋的清单：把**当天预约**（排除已取消、爽约）涉及的款式 `material_json` 按名字聚合，
再和库存对一遍，只有「要 ＞ 存」才算缺。

```
要 1 · 存 0 · 缺 1   待采购     ← 要买
要 1 · 存 1           齐了       ← 够，且已备好
```

库存里根本没建过这个物料，也算缺（采购状态显示「没建库存」）。

![物料页](docs/screenshots/solo-materials.png)

### 库存与领用

- 库存卡片：名称、数量单位、采购状态、成本（赞助物料标「赞助 · 品牌」）。
- 状态筛选：待采购 / 已下单 / 在途 / 已到货 / 已备好，带各自数量。
- **按单领用**：作业单卡片上点「料 未领」→ 抽屉里选料 + 数量 → 领用当场扣库存、写成本快照（赞助物料记 0）。
- 编辑物料：名称、库存、单位、成本、是否赞助（赞助商 + 赞助价值）、采购状态、备注。

![按单领料](docs/screenshots/solo-usage.png)

## 3. 财务

一页交代三件事：这个月赚了多少、明细对不对得上、每一笔能不能追回预约。

```
2026 年 11 月 · 净收入 ¥109.50
收入 168 | 支出 58.50 | 净收入 109.50 | 定金没收 0
✓ 明细求和与汇总一致
收入 1   支出 1   定金 1                    [＋ 记一笔]
11/06  物料支出  — · 补两瓶胶              −58.50
```

- **三本账分开**：收入流水 / 支出流水 / 定金流水，各自计数。
- **对账**：概览的数字来自 SQL 聚合，明细来自逐笔累加，两边比；不一致会把差额标红写出来。
- **可跳回预约**：带预约的流水点一下进当天作业单（`/solo/today?date=`）。
- **记一笔**：方向 + 类别 + 金额 + 备注，尾款和买料都在这里记。

![财务页](docs/screenshots/solo-finance.png)

## 5. 设计取舍

1. **「今天要买的料」从款式清单推，不靠手工登记**。款式上已经写了材料清单，再让人手工列采购单就是重复劳动；聚合 + 对库存，缺口自己就出来了。
2. **对账比的是两条不同的取数路径**。概览用 SQL `SUM`，明细在 Java 里逐笔加。两边都从同一批流水来、但算法不同，真出问题时（比如半路改过数据、分页截断）能看出来。
3. **领用入口放在作业单卡片上**。「这一单用了什么料」是服务的自然延伸；放到物料页再选单反而绕。
4. **赞助物料成本 0 但仍记价值**。账上成本为 0（没花钱），赞助商与价值单独记在物料上，对账时不会把赞助算成支出。

## 6. 验收（17 项，Chromium + CDP）

故事线：一单从收定金到完成，三本流水各自正确。

```
PASS  今天要买的料列出来 — 2 行
PASS  缺口算对 — 封层 要1·存0·缺1；裸胶 要1·存1 齐了
PASS  库存列表渲染 — 2 张
PASS  点「料」打开按单领料
PASS  领用后抽屉里多一条 / 领用自动扣库存 — 1 → 0
PASS  财务概览 / 记收入后概览更新 — 168
PASS  收入/支出/净收入对得上 — 168 | 58.50 | 109.50
PASS  对账一致 — ✓ 明细求和与汇总一致
PASS  三本账各 1 条
PASS  定金账显示「定金收取」 / 明细可跳回预约 — /solo/today?date=2026-11-06
PASS  月度汇总与明细一致 — income 168 / expense 58.5 / net 109.5 / 定金 30 / balanced true
PASS  定金流水独立记账 — 30
PASS  电脑端财务页无横向滚动 / 电脑端物料多列（3 列）
合计 17 项，失败 0 项
```

对应 brief 验收：

- **一单从定金到完成，三本流水正确**：定金流 1 条（30）、收入流 1 条（168 尾款）、支出流 1 条（58.5 买料），完成单后定金账不变（定金不自动抵扣）。
- **月度汇总与明细一致**：`balanced=true`，收入 168、支出 58.5、净收入 109.5。

## 2. 表清单

全部新表统一 `solo_` 前缀，与 `main` 分支既有业务表（`appointment`、`sys_user` 等）物理隔离，`git checkout main` 时互不干扰。

| 表 | 作用 | 关键字段 |
|---|---|---|
| `solo_client` | 客户档案 | `code` 短号（唯一、永不变）、`nickname`、`phone_tail`、`first_visit_date`、`last_visit_date`、`deleted` 软删除 |
| `solo_style` | 款式库 / 作品集 | `duration_min` 标准时长、`price` 标准价、`material_json` 材料清单、`tags`、`enabled` |
| `solo_booking` | 预约单 | `client_id`、`start_at`、`planned_minutes`、`buffer_minutes`（默认 20）、`end_at`、`status`、`source`、`group_id`（连单）、`free_reschedule_used` |
| `solo_booking_item` | 预约项目（连做） | `booking_id`、`style_id`（可空）、`style_name`/`price` 快照、`duration_min`、`addon`、`seq` |
| `solo_slot_block` | 营业安排 | `work_date`、`start_time`、`end_time`、`type`（营业/休息/外出/机动位） |
| `solo_deposit_flow` | 定金流水 | `booking_id`、`type`（收取/抵扣/退还/没收）、`amount`、`happened_at` |
| `solo_money_flow` | 收支流水 | `direction`（IN/OUT）、`category`、`amount`、`happened_at`、`booking_id`（可空） |
| `solo_material_item` | 物料库存 | `unit_cost`、`quantity`、`sponsored`/`sponsor_name`/`sponsor_value`、`purchase_status` |
| `solo_material_usage` | 按单领用 | `booking_id`、`material_id`、`quantity`、`cost_snapshot` |
| `solo_booking_change` | 改期/顺延/插队 | `type`、`old_start`、`new_start`、`initiator`、`hours_before`、`deposit_action`、`notified` |
| `solo_booking_event` | 状态事件（P2 规则 7 前置） | `action`、`from_status`、`to_status`、`operator` |

## 3. ER 文字说明

```
solo_client 1 ──N solo_booking 1 ──N solo_booking_item
                      │  │  │  │
                      │  │  │  └──N solo_booking_event     （状态留痕）
                      │  │  └─────N solo_booking_change    （改期/顺延/插队）
                      │  └────────N solo_deposit_flow      （定金四条流水）
                      └───────────N solo_material_usage ──N solo_material_item

solo_style 1 ──N solo_booking_item（style_id 可空，名称与单价快照到 item）
solo_slot_block   独立按 work_date 归属日期，不建外键；空档 = 营业段 − 已占用段
solo_money_flow   独立记账，booking_id 可空，可从明细回跳预约
```

关系约定：

1. **客户 → 预约**：一对多。删除客户是软删除（`deleted = 1`），历史预约保留，展示时标「客户已删除」（P8 验收 9）。
2. **预约 → 项目**：一对多。单条预约的 `planned_minutes` = 各项目 `duration_min` 之和；占用 = `planned_minutes + buffer_minutes`。
3. **款式 → 项目**：款式可下架（`enabled = 0`）或改名改价，项目里保存名称与单价快照，历史单不受影响。
4. **预约 → 定金流水**：只记流水，不存「已收/已退」状态字段；余额由 `COLLECT + OFFSET + REFUND + FORFEIT` 明细推导（brief：不用状态推断金额）。
5. **预约 → 物料领用 → 物料库存**：领用写 `cost_snapshot`，后续调价不影响历史成本；赞助物料 `unit_cost = 0`，赞助商与价值记在 `solo_material_item`。
6. **预约 → 变更记录**：改期/顺延/插队各一行，`notified` 支撑「待通知清单」。
7. **营业安排独立**：`solo_slot_block` 描述当天哪些时段可以接单，与预约不做外键；空档和「可塞 N 分钟」在应用层用时间段相减算出。

建表与 `schema.sql` 保持同一套约定：InnoDB + utf8mb4、不建外键（一致性由应用层保证）、`created_at` / `updated_at` 带默认值。

## 4. 状态机

预约状态（`solo_booking.status`，常量见 `SoloBookingStatus`）：

```
LEAD 线索 → WAIT_DEPOSIT 待定金 → BOOKED 已定档 → ARRIVED 到店 → IN_SERVICE 服务中 → COMPLETED 已完成
                                        │
                                        └─ 分支：RESCHEDULED 已改期 / CANCELLED 已取消 / NO_SHOW 爽约
```

- **占用时段**只判 `BOOKED` / `ARRIVED` / `IN_SERVICE`（`BookingGuard.OCCUPY_STATUSES`）；到店后必然在店里占着时间，不计入会让作业单出现重叠。
- 改期采用「同一条预约原地改时间 + `solo_booking_change` 留痕」，状态仍为 `BOOKED`；`RESCHEDULED` 保留给「原单作废保留、另开新单」的追溯场景（如退定并撤销后重排）。

物料采购状态独立（`solo_material_item.purchase_status`）：

```
TODO 待采购 → ORDERED 已下单 → SHIPPING 在途 → ARRIVED 已到货 → READY 已备好
```

## 5. 验证步骤

### 5.1 建表脚本（已执行，可重复）

```bash
cd backend
mysql -uroot -p123456 < src/main/resources/db/schema_solo.sql   # 第一次
mysql -uroot -p123456 < src/main/resources/db/schema_solo.sql   # 第二次，用于验证可重复
mysql -uroot -p123456 -e "SHOW TABLES FROM nail_demo LIKE 'solo%';"
```

预期：两次均退出码 0，不报 `Table already exists`；返回 11 张 `solo_*` 表。

### 5.2 编译

```bash
cd backend
mvn -B -o -Daether.syncContext.named.factory=noop compile
```

本机 `~/.m2` 对当前沙箱只读，Maven 默认的文件锁会报 `Could not open file channel for ... .locks`。加 `-Daether.syncContext.named.factory=noop -o` 即可正常编译；换到可写环境时直接 `mvn compile`。

预期：`BUILD SUCCESS`，127 个源文件编译通过（含本次新增的 31 个类：11 实体 + 11 Repository + 9 常量）。

### 5.3 启动校验

```bash
cd backend
mvn -B -o -Daether.syncContext.named.factory=noop spring-boot:run
```

预期：`Started NailApplication`，无 Hibernate 报错；启动后 `SHOW TABLES` 仍为原有 14 张 + 新增 11 张，说明实体映射与脚本一致、`ddl-auto: update` 没有额外建表或改表。

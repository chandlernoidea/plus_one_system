# P5 · 客户档案与款式库（含专用登录 / 返回导航 / 双端布局）

> 分支 `feat/solo-studio`；事实来源 `docs/solo/00-brief.md`。
> 本轮除了 P5 的客户与款式，还落了三个体验改造：专用登录页、二级页返回、电脑+手机双端。

## 2. 三个体验改造

### 2.1 专用登录页 `/solo/login`

原来落到的是多角色版登录页（要讲三个角色怎么试）。现在：

- 根路径 `/` 直接进单人版，未登录由守卫送到 `/solo/login`；
- 一屏两栏：左边「指间工作室 / 登录 / 档期与现金流的台账」，右边一句定位；手机上只有一栏；
- 只认管理员账号，其他角色登录会被挡回并提示「这个账号不是老板账号」；
- 底部保留两个小入口：填入演示账号、多角色演示入口（`/login` 还在，答辩要用）。

### 2.2 二级页「← 返回」

详情页、款式库、财务这类二级页，左上角有 `← 客户` / `← 今天`，不用靠浏览器后退键。
实现是外壳的一个可选 prop：

```vue
<SoloLayout back-to="/solo/clients" back-label="客户">
```

`back-to="back"` 时走浏览器后退，传路径则直接跳转。

### 2.3 电脑 + 手机一套代码

断点 900px（作业单的双栏是 1000px）：

| | 手机（< 900px） | 电脑（≥ 900px） |
|---|---|---|
| 导航 | 报头两行 + 底部三入口 | 导航进报头一行，底部栏收起 |
| 版心 | 560px | 1080px |
| 客户列表 | 单列 | `auto-fill minmax(300px)`，实测 3 列 |
| 款式网格 | 2 列 | `auto-fill minmax(220px)`，实测 4 列 |
| 客户详情 | 单列 | 左档案（sticky）右历史，340 + 1fr |
| 作业单 | 时间轴 + 下方提醒 | 左时间轴 + 右提醒栏（340px，sticky） |
| 抽屉 | 贴底 | 贴底但限宽 560，居中 |

没有为桌面另写一套页面：同一批组件靠媒体查询换排布，省得两端行为分叉。

## 3. 客户档案

- **列表**：按最近到访倒序（后端排好），搜索短号 / 昵称 / 手机后四位，实测搜 `9911` 精确命中 1 位。
- **新建**：短号自动生成（`#C001` 递增、跳过占用），昵称、后四位、来源、常用色号、备注。
- **重名提示**：输入昵称 400ms 后查同名，提示「已有同名客户 #C002，建议加个区分词（如阿岚-长甲）」——**不替用户改名**。
- **详情**：档案（色号 / 备注）+ 统计（预约 / 完成 / 做过的款）+ 做过的款与次数 + 历史预约（点一行进当天作业单）。
- **删除**：软删除，二次确认里写明「客户不再出现在列表，但历史预约、定金与流水都保留」。

![客户详情](docs/screenshots/solo-client-detail.png)

## 4. 款式库

- 网格卡片：封面（没图用款名首字占位）、名称、时长、价格、标签；下架的打灰并标「已下架」。
- 新建 / 编辑：名称、封面（复用既有 `ImageUploader`）、标准时长、标准价、标签（英文逗号）、材料清单。
- **材料清单**在界面上是「每行一项：底胶 1」，存库仍是 JSON 数组——老板不用手写 JSON。
- **导出案例图**：按标签筛 → 现场用 canvas 拼 1080×1440 竖版九宫格 → 预览 → 保存 PNG。带斜向水印「指间工作室 · SOLO」，格子不足 9 个会留白并提示。

![导出案例图](docs/screenshots/solo-export.png)

## 5. 后端增量

| 改动 | 说明 |
|---|---|
| `solo_client.color_notes` | 常用色号，schema 里用 information_schema 判断后动态 ALTER，可重复执行 |

| `GET /api/solo/clients/check-name?nickname=` | 同名客户，供新建时提示 |

## 6. 设计取舍

1. **常用色号是档案里的手记，不从历史推断**。历史单里没有色号字段，靠款式名猜会编数据；不如让老板写一句「#E03 裸粉，怕深色」。
2. **导出放前端 canvas，不做后端图片服务**。九宫格是纯排版，浏览器里 20ms 就能出图；后端做就要引图片库、管临时文件，还得考虑并发。「保存图片」直接 `canvas.toDataURL()` + `<a download>`，不需要额外接口。
3. **电脑端不另做一套页面**。单人版的功能面很窄，媒体查询换排布足够；真做两套，以后每加一个功能都要改两处。
4. **重名不自动加后缀**。人的称呼是老板自己的事，系统只提示，改不改由人决定。

```

PASS  详情有历史预约与做过的款 — {"history":1,"usage":1,"stats":["1","0","1"]}
PASS  详情页有返回按钮 — ← 客户 / 点返回回到客户列表
PASS  款式网格渲染 / 款式库有返回今天
PASS  新建款式后 +1 / 点卡片进编辑
PASS  导出预览是 canvas 生成的 PNG — 1080×1440
PASS  保存图片触发下载 — 款式案例-全部-*.png
PASS  390px 无横向滚动
PASS  电脑端导航挪到报头 / 作业单双栏 / 客户列表 3 列 / 款式网格 4 列
PASS  1280px 无横向滚动
合计 23 项，失败 0 项
```

对应 brief 验收：

- **短号不重复**：唯一键 + 生成时跳过已占用（`nextCode`），重名检查走的是昵称而不是短号。
- **导出图可生成并保存**：预览是 `data:image/png`、1080×1440，保存触发下载文件名 `款式案例-…png`。

电脑端：作业单见 `docs/screenshots/solo-desktop-today.png`，款式库见 `docs/screenshots/solo-desktop-styles.png`。

# 单人美甲工作室版 · 设计与实施说明

> 分支：`feat/solo-studio`
> 状态：设计已定稿，进入实现
> 本文是这条产品线的唯一事实来源；新会话先读本文，再按「实施提示词包」逐段执行。

## 1. 一句话定位

**单人美甲工作室的「档期 + 现金流」台账**：老板 = 美甲师 = 唯一使用者，用来防止漏人、漏时间、漏款、漏料。

它回答四个问题：

1. 今天给谁做、做什么款、要多久？
2. 材料买了没有、够不够？
3. 定金收了没有、这单退不退？
4. 这个月收入支出对得上吗？

它**不是** SaaS，**不面向客户**，**不做营销工具**。

## 2. 与现有系统的关系

| 现有能力 | 单人版处理 |
|---|---|
| 三角色 + 行级权限 | 砍掉，只保留一个管理员账号 |
| 多美甲师日程 | 砍掉，日程就是「我的」 |
| 客户注册 / 自助预约 | 砍掉，客户是档案不是账号 |
| 预约状态机、时间槽、冲突校验 | 复用，改为「我的日程 + 机动位」 |
| 月度结算（底薪/提成/评价奖惩） | 替换为简单收支：定金、尾款、物料成本 |
| 前端设计系统（编辑式纸面风格） | 复用 |
| 物料工单 | 升级为「库存 + 按单领用 + 采购状态」 |

分支策略：

- `main` 保持多角色版本，用于论文答辩演示，不动；
- `feat/solo-studio` 从 `main` 切出，复用技术栈与设计系统，逐步替换领域模块；
- 需要回到答辩版本：`git checkout main`。

## 3. 已锁定的决策

| 项 | 结论 |
|---|---|
| 用户 | 只有老板一人；客户、员工、多店都不存在 |
| 营业时间 | 默认模板（如 10:00–20:00）+ 每日例外；实际常落在 8:30–22:30 |
| 缓冲 | 默认 20 分钟，可按单覆盖 |
| 并发 | 一个时段只服务一位客户；连做/连单按串行排 |
| 时长 | 款式带标准时长，建单时可改，改动留痕 |
| 客户标识 | `#C012` 短号（自动生成、永不变）+ 昵称 + 手机后 4 位（选填） |
| 客户查找 | 短号 / 昵称 / 手机后四位，三者都能命中 |
| 连单 | 同一客户多项目、两位朋友先后到店，两种都支持 |
| 定金 | 固定 30 元；收 / 抵扣 / 退还 / 没收 四条流水 |
| 改期 | 距开始 ≥48 小时且未用过免费改期 → 免费改一次；否则提示扣定金 |
| 老板让位 | 可手动「退定并撤销」，必须选原因（客户原因 / 店铺原因 / 纠纷） |
| 插队 | 只发生在已有客户取消/改期释放时段之后；可选「顺延」或「新建插单」 |
| 通知 | 系统只提醒老板，生成「今天要发微信」清单 + 可复制话术 |
| 物料 | 库存制 + 按单领用；记金额；赞助物料成本记 0，另记赞助商与赞助价值 |
| 财务 | 定金流水、收入流水、支出流水分开记；月度收支对平、明细可查 |
| 数据迁移 | 只导入客户（CSV），不导历史预约 |
| 设备 | 手机优先，桌面只做适配 |
| 款式库 | 兼作品集：可按标签筛选，导出竖版案例图供发小红书/微信 |

明确不做：在线支付、客户自助端、小程序、评价体系、营销分析、多美甲师排班、自动排班算法、复杂权限。

## 4. 铁律

1. **只有一个用户**。任何「角色」「权限」「多租户」的设计都不属于这条产品线。
2. **客户是档案**，不是账号；不收集敏感个人信息（过敏史、皮肤情况改为到店当面确认）。
3. 技术栈沿用：Vue 3 + Vite + Element Plus + Pinia；Spring Boot 3 + JPA + MySQL；复用 `src/styles/tokens.css` 等设计系统。
4. 建单必须能 **3 分钟内** 完成；手机端不横向滚动。
5. 每轮先给「表结构 / 接口 / 页面结构」，确认后再写代码。
6. 每轮结束必须：前端 `npm run build`、后端 `mvn compile` 通过，并手工验证主流程、写清验证步骤。
7. 不做无关重构、不新增未被要求的依赖、不写「未来可能用到」的抽象。

合规红线：手机号选填、数据可删除、案例图用于宣传前单独取得客户同意。

### P1 · 数据模型

```text
任务：设计并落地单人版数据模型（MySQL + JPA 实体）。

对象：
1. client：短号 code（#C001，自动生成、永不变）、昵称、手机后4位、来源、备注、首访、最近到访。
2. style：款式库。名称、封面图、标准时长、标准价、材料清单 JSON、标签、是否启用。
3. booking：client_id、开始时间、预计时长、缓冲（默认20，可改）、状态、来源、备注、连单 group_id。
4. booking_item：一个预约下的多个项目（款式、时长、价格、是否加项）。
5. slot_block：营业安排。日期、起止、类型（营业/休息/外出/机动位）。
6. deposit_flow：定金流水（收取/抵扣/退还/没收）、金额、时间、原因、关联预约。
7. money_flow：收支流水（方向、类别、金额、时间、关联预约、备注）。
8. material_item：库存（名称、单位、成本、数量、是否赞助、赞助商、赞助价值）。
9. material_usage：按单领用（booking_id、material_id、数量、成本快照）。
10. booking_change：改期/顺延/插队记录（原时间、新时间、发起方、提前小时数、定金处理、是否已通知）。

预约状态机：线索 → 待定金 → 已定档 → 到店 → 服务中 → 已完成；分支：已改期、已取消、爽约。
物料状态独立：待采购 → 已下单 → 在途 → 已到货 → 已备好。

交付：schema 增量脚本（可重复执行）、JPA 实体与 Repository、ER 文字说明。
验收：mvn compile 通过；脚本执行后表结构正确；给出 3 条示例数据插入结果。
```

### P2 · 后端核心规则

```text
任务：实现 /api/solo/* 接口与业务规则（不要动现有 /api/*）。

接口：客户 CRUD（按短号/昵称/后四位搜索）、款式 CRUD、预约（创建/改期/取消/到店/开始/完成/爽约）、
排期查询（日/周，含 slot_block）、定金（收取/抵扣/退还/没收）、财务（月度汇总+明细）、物料（库存/领用/采购状态）。

规则：
1. 占用 = 各项目时长之和 + 缓冲；缓冲默认 20，可按单覆盖。
2. 同一时段只允许一条「已定档/服务中」；冲突返回 409 + 冲突单摘要，不静默覆盖。
3. 改期：距开始 ≥48h 且未用过免费改期 → 免费改并记一次；否则标记「需扣定金」，由老板手动选择退定/没收/仍免费。
4. 定金固定 30；四条流水严格分开，不用状态推断金额。
5. 插队只允许插入取消/改期释放的空档；校验「新单时长 + 缓冲 ≤ 空档」，超出拒绝。
6. 顺延：平移后续预约，返回「影响 N 单」清单，不自动通知。
7. 每次状态变化写 booking_event（时间、动作、操作者、备注）。

交付：Controller + Service + DTO + 单元测试（改期规则、冲突检测、插队校验各至少 1 例）。
验收：curl 覆盖「建单 → 收定金 → 改期 → 退定」完整链路。
```

### P3 · 前端骨架 + 今日作业单

```text
任务：单人版前端骨架与「今日作业单」（路由 /solo/*，移动优先）。

骨架：单账号登录；三入口「今天 / 排期 / 客户」，款式与财务放二级；复用现有设计系统。

今日作业单：
- 顶部：今天 N 单、总时长、定金合计、待采购件数；
- 时间轴默认 8:30–22:30，按当天营业安排裁剪；
- 每单卡片：时间与时长、#短号 + 昵称、款式缩略图、项目列表、定金状态、物料是否齐、备注；
- 卡片操作：到店 / 完成 / 改期 / 取消；
- 机动位与空档浅色标出，空档显示「可塞 N 分钟」；
- 「今天要发的提醒」折叠区：需要发微信的客户 + 一键复制话术。

验收：390px 不横向滚动；一屏能看到当天全部单；建单到完成可点通。
```

### P4 · 排期与插队

```text
任务：周排期页与插队/顺延交互。

- 周视图 7 列，显示预约块与机动位；点某天进入作业单；
- 空档识别：任意两单之间的可用时间，标注「可塞 N 分钟」；
- 插队：从空档点「插一单」→ 选客户/款式 → 校验时长 → 建单（来源标记插队）；
- 顺延：选中后续预约 → 预览平移结果 → 确认后逐单改期并生成「待通知清单」；
- 冲突：允许强排但标红，作业单顶部提示冲突数。

验收：取消一单后空档立即出现且能插入；顺延 3 单后时间与通知清单正确。
```

### P5 · 客户与款式库

```text
任务：客户档案与款式库。

客户：按最近到访排序；搜索支持短号/昵称/后四位；新建自动生成短号；重名提示加区分词；
详情显示历史预约、做过的款式、常用色号、备注。

款式库：网格卡片（封面、名称、时长、价格、标签）；新建/编辑（封面、材料清单、时长、价格）；
「导出案例图」：按标签筛选后拼成竖版九宫格图，带水印，可直接发小红书。

验收：短号不重复；导出图可生成并保存。
```

### P6 · 物料与财务

```text
任务：物料库存与三类流水页面。

物料：库存列表；按单领用自动扣库存并写成本快照；采购状态按预约聚合「今天要买的料」；
赞助物料成本记 0、另记赞助商与价值。

财务：月度概览（收入、支出、净收入、定金没收额）；三本明细可跳回预约；
对账校验：收入 − 支出 = 明细求和，不一致标出差异项。

验收：一单从定金到完成，三本流水正确；月度汇总与明细一致。
```

### P7 · 提醒、导入与收尾

```text
任务：提醒、CSV 导入、设置页。

提醒：每天生成「今天要发微信」清单（昨日未确认、今日、明日），每条带可复制话术；只提醒老板。

导入：CSV 导入客户（昵称、手机后四位、来源、备注），预览前 5 行，同名标黄；不导历史预约。

设置：营业时间模板、缓冲默认值、定金金额、免费改期阈值；客户/预约/流水 CSV 导出；
一键演示数据：3 客户、5 款式、今天 4 单（含 1 单连做、1 个空档）。

验收：新环境一条命令起演示数据；导入 20 条客户无重复短号。
```

### P8 · 验收清单

```text
任务：逐项验收，输出「通过/不通过 + 证据」。

1. 3 分钟建单：选客户 → 选款式 → 定时间 → 收定金 → 保存。
2. 连做：两个项目总时长 = 90 + 120 + 缓冲，日程正确。
3. 改期：60h 内免费改一次；48h 内提示扣定金；老板可退定并撤销。
4. 插队：取消一单后插 90 分钟成功；插 180 分钟被拒。
5. 冲突：同段两单标红且不丢数据。
6. 财务：一天 3 单（1 单爽约没收定金）→ 月度汇总与明细一致。
7. 物料：一单领用 2 种，库存扣减、成本计入；赞助物料成本 0 但记价值。
8. 移动端：390px 作业单一屏可读，无横向滚动。
9. 删除客户后历史预约保留并标记「客户已删除」。
10. npm run build 与 mvn package 均通过。
```

## 2. 接口清单

所有接口在 `/api/solo` 下，沿用现有 JWT 鉴权（`/api/**` 需登录），登录后带 `Authorization: Bearer <token>`。

## 3. 规则 → 实现映射

| brief 规则 | 实现位置 | 行为 |
|---|---|---|
| 1. 占用 = 各项目时长之和 + 缓冲，缓冲默认 20 可覆盖 | `SoloScheduleRules.endOf` + `BookingService.persist` | `plannedMinutes` 取项目时长之和，`endAt = startAt + planned + buffer` |
| 2. 同段只允许一条已定档/服务中，冲突 409 + 摘要 | `BookingGuard.assertNoConflict` + `SoloExceptionHandler` | 用一条 SQL 判 `startAt < end AND endAt > start`，冲突返回 HTTP 409，`data` 里是冲突单摘要数组；建单带 `force=true` 可跳过校验（P4 的「强排」，由前端标红提示） |
| 3. 改期 ≥48h 且未用过免费 → 免费一次；否则提示扣定金 | `SoloScheduleRules.isFreeReschedule` + `BookingService.reschedule` | 不满足时**不改期**，返回 `needDepositDeduction=true` 与话术；老板再传 `depositDecision` 才落地 |
| 4. 定金固定 30，四条流水分开，不用状态推断金额 | `DepositService` + `DepositLedger` | 累计收取不得超过 30；余额与状态全部由流水推导 |
| 5. 插队只允许插进取消/改期释放的空档 | `SlotAvailabilityService` + `BookingService.jump` | 先算当天空档，再校验 `时长 + 缓冲 ≤ 空档`，塞不下 409 |
| 6. 顺延平移后续预约，返回影响清单，不自动通知 | `BookingService.previewShift / shift` | 预览不写库；执行逐单平移并写 `solo_booking_change(notified=0)` |
| 7. 每次状态变化写 booking_event | `BookingGuard.recordEvent` | 建单、定档、到店、开始、完成、改期、顺延、取消、爽约均留痕 |

补充约定：

- **待定金不占档**。建单可传 `status=WAIT_DEPOSIT` 先占位；收定金时若时段已被别人占，`COLLECT` 会被 409 拦下，不会把冲突带进「已定档」。
- **改期用原地改时间**，状态保持 `BOOKED`，变更写 `solo_booking_change`；`RESCHEDULED` 仍保留给「原单作废保留、另开新单」的追溯场景。
- **占用状态**为 `BOOKED / ARRIVED / IN_SERVICE`：到店后必然在店里占着时间，不计入会让作业单出现重叠。

## 4. 排期与空档

- 营业窗口取 `solo_slot_block` 中 `OPEN/FLEX` 的段并合并；当天没配置时用 8:30–22:30 兜底。
- 空档 = 营业窗口 − 占用窗口，只保留 ≥15 分钟的段，前端据此显示「可塞 N 分钟」。
- 插队插入点必须在某个空档内，且 `开始时刻 + 时长 + 缓冲` 不超过该空档的结束时刻。

## 5. 单元测试

`mvn test` 共 12 例，覆盖 brief 要求的改期规则 / 冲突检测 / 插队校验：

| 用例 | 断言 |
|---|---|
| `occupancyAddsBuffer` | 10:00 + 90 + 20 → 11:50 |
| `rescheduleIsFreeOnlyWhenQualified` | 60h 免费、48h 整免费、47h 不免费、用过免费额度不免费 |
| `conflictOnlyWhenOverlapping` | 交叉/包含算冲突；首尾相接、紧邻在前不算 |
| `jumpRequiresGapFits` | 80 分钟进 90 分钟空档通过；110 分钟被拒；起点后剩 60 分钟被拒 |
| `freeGaps` / `gapContaining` | 空档切分正确；贴着结束点不算命中 |
| `DepositLedgerTest` 6 例 | 未收/已收/已退/没收/抵扣 五种状态，脏类型不参与金额计算 |

## 7. 验证步骤

```bash
# 1. 编译
cd backend
mvn -B -o -Daether.syncContext.named.factory=noop compile

# 2. 单元测试（本机需可写仓库副本，见下）
mvn -B -Dmaven.repo.local=target/m2repo -Daether.syncContext.named.factory=noop test

# 3. 起服务
mvn -B -Dmaven.repo.local=target/m2repo -Daether.syncContext.named.factory=noop spring-boot:run

# 4. 手工链路（另开终端）
TOKEN=$(curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"123456"}' | jq -r .data.token)
curl -s -H "Authorization: Bearer $TOKEN" localhost:8080/api/solo/schedule/day?date=2026-11-14 | jq
```

环境备注（本机沙箱）：`~/.m2` 只读，Maven 默认文件锁会报 `Could not open file channel for … .locks`，因此上面的命令都带 `-Daether.syncContext.named.factory=noop`；首次跑测试前把仓库复制一份到可写目录：

```bash
cp -a ~/.m2/repository backend/target/m2repo
```
